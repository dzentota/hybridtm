# HybridTM

**HybridTM** is a PHP threat-modeling toolkit that keeps architecture models, code annotations, and risk analysis in sync:

- A **PHP DSL file** declares infrastructure (assets, trust boundaries, data types, **Abuser Stories**).
- **PHP 8 attributes** (`#[DataFlow]`, `#[Mitigation]`, `#[AbuserStory]`, …) live in application source.
- **`hybridtm compile`** merges both into [Threagile](https://threagile.io)-compatible YAML.
- **`hybridtm analyze`** runs the Rule Engine against a Knowledge Base — and can verify that every Abuser Story is mitigated in code.

The compiler statically analyses the code (no execution).

---

## Problem Statement

Existing threat-modeling approaches have well-known failure modes:

- **PyTM / traditional TMaC** — the threat model lives in a separate file disconnected from the real codebase. It drifts within weeks, generates false positives, and requires a dedicated security engineer to maintain.
- **Manual TMiC (Threatspec-style)** — developers are expected to write security annotations by hand while also delivering features. In practice, annotations are skipped, incomplete, or added retroactively.
- **Architecture-only DFDs** — useful for STRIDE workshops, but product teams think in User Stories; security acceptance criteria never get checked against the shipped code.

HybridTM's answer:

1. **Externalise classic Threagile analysis** where you want DFD/PDF reports — compile to YAML and let Threagile score risks.
2. **Run HybridTM's Rule Engine** for KB-driven, explainable findings (`RuleTrace`) and **Abuser Story coverage**.
3. **Automate annotation.** Rich attributes are ideal for AI coding assistants (`SKILL.md` / Copilot / Cursor) whenever code crosses a service boundary or implements a control tied to a story.

The result is a **Continuous Threat Modeling** pipeline: annotations generated by AI, compiled and analysed in CI/CD, with story-level gates (`--fail-on-uncovered-stories`).

## Core Architecture

```
┌─────────────────────────────────────────────────────────┐
│  1. AI Copilot Skill (SKILL.md)                         │
│     Emits #[DataFlow] / #[Mitigation] / #[AbuserStory]  │
└───────────────────────────┬─────────────────────────────┘
                            │
              ┌─────────────▼──────────────┐
              │  src/**/*.php              │
              │  #[AssetId] #[DataFlow]    │
              │  #[Mitigation]             │
              │  #[AbuserStory('…')]       │
              └─────────────┬──────────────┘
                            │
          ┌─────────────────▼──────────────────┐
          │  2. Infrastructure DSL             │
          │     threat-model.php               │
          │     Assets · TrustBoundaries ·     │
          │     AbuseCase (Abuser Stories)     │
          └────────┬───────────────┬───────────┘
                   │               │
     ┌─────────────▼───┐   ┌───────▼──────────────┐
     │ 3a. compile     │   │ 3b. analyze          │
     │ → Threagile YAML│   │ KB Rule Engine       │
     └────────┬────────┘   │ + story coverage     │
              │            └───────┬──────────────┘
              ▼                    ▼
        Threagile reports    Findings + storyCoverage
```

| Layer | Files | Responsibility |
|-------|-------|----------------|
| AI Skill | `SKILL.md` | Teaches the IDE AI which attribute to write and when |
| Infrastructure DSL | `threat-model.php`, `src/DSL/` | Declares nodes, data, trust zones, Abuser Stories |
| PHP 8 Attributes | `src/**/*.php`, `src/Attributes/` | Annotates flows, mitigations, story links |
| Compiler / Analyzer | `bin/hybridtm`, `src/Compiler/`, `src/Analysis/` | YAML export + Rule Engine + coverage |
| Studio | `apps/studio/` | Visual canvas, Stories panel, live findings |

## Quick Start

### 0. Bootstrap with the wizard (recommended)

```bash
php bin/hybridtm init --out=threat-model.php
```

### 1. Write an infrastructure DSL file

```php
<?php // threat-model.php
declare(strict_types=1);
require_once __DIR__ . '/vendor/autoload.php';

use HybridTM\DSL\{AbuseCase, DataAsset, TechnicalAsset, ThreatModel, TrustBoundary};
use HybridTM\Enums\{AssetType, BusinessCriticality, Confidentiality,
    Machine, Technology, TrustBoundaryType};

$model = new ThreatModel('My Service');
$model->businessCriticality = BusinessCriticality::Critical;

$secret = new DataAsset('api-key', 'API Key');
$secret->confidentiality = Confidentiality::StrictlyConfidential;
$model->addDataAsset($secret);

$api = new TechnicalAsset('api', 'REST API');
$api->type = AssetType::Process;
$api->technology = Technology::WebServiceRest;
$api->machine = Machine::Container;
$model->addTechnicalAsset($api);

$db = new TechnicalAsset('db', 'Database');
$db->type = AssetType::Datastore;
$db->technology = Technology::Database;
$db->dataAssetsStored = ['api-key'];
$model->addTechnicalAsset($db);

$attacker = new TechnicalAsset('external-attacker', 'External Attacker');
$attacker->type = AssetType::ExternalEntity;
$attacker->traits = ['threat_actor'];
$model->addTechnicalAsset($attacker);

$story = new AbuseCase('steal-api-key', 'Exfiltrate API keys from the datastore');
$story->asA = 'anonymous attacker';
$story->iWant = 'read api-key records';
$story->soThat = 'impersonate the service';
$story->actorId = 'external-attacker';
$story->assetIds = ['db'];
$story->requiredCwes = ['CWE-312'];
$model->addAbuseCase($story);

$vpc = new TrustBoundary('vpc', 'VPC', TrustBoundaryType::NetworkCloudProvider);
$vpc->addAssets('api', 'db');
$model->addTrustBoundary($vpc);

return $model;
```

### 2. Annotate your code

```php
<?php
namespace App;

use HybridTM\Attributes\{AbuserStory, AssetId, DataFlow, Mitigation};
use HybridTM\Enums\{Authentication, Authorization, MitigationStatus, Protocol};

#[AssetId('api')]
class ApiController
{
    #[DataFlow(
        target: 'db',
        protocol: Protocol::JdbcEncrypted,
        authentication: Authentication::Credentials,
        authorization: Authorization::TechnicalUser,
        dataSent: ['api-key'],
        dataReceived: ['api-key'],
    )]
    #[AbuserStory('steal-api-key')]
    #[Mitigation(
        cwe: 'CWE-312',
        description: 'Secrets encrypted at rest',
        status: MitigationStatus::Mitigated,
    )]
    public function getSecret(string $key): string { ... }
}
```

### 3. Compile and analyze

```bash
php bin/hybridtm compile \
    --infra=threat-model.php \
    --source=src/ \
    --out=threagile.yaml

php bin/hybridtm analyze \
    --infra=threat-model.php \
    --source=src/ \
    --kb=vendor/hybridtm/hybridtm/apps/api/kb \
    --format=table \
    --fail-on-uncovered-stories
```

## The Two-Part Model (+ stories)

| Part | File | Purpose |
|------|------|---------|
| Infrastructure DSL | `threat-model.php` | Declares assets, trust zones, data types, Abuser Stories |
| Code Attributes | `src/**/*.php` | Annotates real flows, mitigations, story links |

The DSL describes the **architecture and abuse scenarios**; the attributes describe the **behaviour and evidence**.

## Command Reference

```
php bin/hybridtm init [options]
php bin/hybridtm compile [options]
php bin/hybridtm analyze [options]

Options (init):
  --out=PATH        Output path for generated DSL file  [default: threat-model.php]

Options (compile):
  --infra=PATH      Path to the infrastructure DSL file  [default: threat-model.php]
  --source=DIR      Source directory to scan for attributes  [default: src/]
  --out=PATH        Output path for Threagile YAML  [default: threagile.yaml]

Options (analyze):
  --infra=PATH      Path to the infrastructure DSL file  [default: threat-model.php]
  --source=DIR      Scan for #[Mitigation] / #[AbuserStory] (enables hasMitigationFor + story coverage)
  --kb=DIR          Knowledge-base directory (repeatable)
  --format=…        table | json | sarif  [default: table]
  --min-severity=…  Filter displayed findings  [default: low]
  --fail-on=…       Exit non-zero if any finding reaches this severity
  --fail-on-uncovered-stories  Exit non-zero if any Abuser Story is uncovered/partial
  --check-stories   Always compute story coverage
  --include-suppressed  Keep findings closed by riskTracking
```

## Available Attributes

| Attribute | Target | Description |
|-----------|--------|-------------|
| `#[AssetId(string $id)]` | Class | Maps class to a DSL TechnicalAsset |
| `#[DataFlow(target, protocol, ...)]` | Method/Function | Declares a communication link |
| `#[Mitigation(cwe, description, status)]` | Class/Method/Function | Records a security control |
| `#[AbuserStory(string $id)]` | Class/Method/Function | Links code to an Abuser Story (`AbuseCase`) |
| `#[ProcessesData(dataAssets: [...])]` | Class/Method | Declares data asset processing |

## Abuser Stories (overview)

Product teams write security acceptance criteria as attacker-shaped stories. HybridTM verifies them against code:

1. Declare `AbuseCase` in the DSL (or Stories panel in Studio).
2. Implement controls with `#[Mitigation]` and tag them `#[AbuserStory('id')]`.
3. Gate CI with `analyze --source=… --fail-on-uncovered-stories`.

Full guide: [docs/en/guide/abuser-stories.md](docs/en/guide/abuser-stories.md).

## Generating Diagrams and Threat Reports

`threagile.yaml` is consumed directly by [Threagile](https://threagile.io). All diagrams and reports are generated by Threagile — HybridTM only produces the YAML input.

### Run Threagile via Docker (recommended)

```bash
mkdir -p threagile-output
docker run --rm \
  -v "$(pwd):/work" \
  threagile/threagile:latest \
  --model /work/threagile.yaml \
  --output /work/threagile-output
```

> **Note:** The output directory must exist before running — Threagile does not create it automatically.

### Data Flow Diagram

```
threagile-output/data-flow-diagram.pdf
```

### Relevant Threat Report

```
threagile-output/risks.json
threagile-output/risks.xlsx
threagile-output/report.pdf
```

### Tracking risk decisions

Use `HybridTM\DSL\RiskTracking` keyed by a finding `stableId` from `hybridtm analyze`, or edit Threagile `risk_tracking` in YAML.

### CI/CD integration

```yaml
# .github/workflows/threat-model.yml
- name: Compile threat model
  run: php bin/hybridtm compile --infra=threat-model.php --source=src/ --out=threagile.yaml

- name: Rule Engine + Abuser Story coverage
  run: |
    php bin/hybridtm analyze \
      --infra=threat-model.php \
      --source=src/ \
      --kb=vendor/hybridtm/hybridtm/apps/api/kb \
      --fail-on=high \
      --fail-on-uncovered-stories

- name: Run Threagile analysis
  run: |
    mkdir -p threagile-output
    docker run --rm \
      -v "${{ github.workspace }}:/work" \
      threagile/threagile:latest \
      --model /work/threagile.yaml \
      --output /work/threagile-output

- name: Upload artifacts
  uses: actions/upload-artifact@v4
  with:
    name: threat-model-report
    path: threagile-output/
```
