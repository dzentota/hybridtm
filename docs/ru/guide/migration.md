# Миграция с чистого `hybridtm`

Если вы начинали только с библиотеки `hybridtm/hybridtm` (DSL +
атрибуты кода + `hybridtm analyze`/`compile`) и хотите получить
персистентность Studio, мультитенантность и редактор-холст, менять в
существующей настройке ничего не нужно — Studio дополняет, а не
заменяет.

## Ваш DSL продолжает работать

`threat-model.php` и любые атрибуты `#[DataFlow]`/`#[Mitigation]` в
вашем коде не затрагиваются. `PhpDslWriter`/`PhpDslReader`
обеспечивают двустороннее преобразование того же формата файлов, что
используют эндпоинты экспорта/импорта Studio, поэтому написанную
вручную модель можно импортировать напрямую:

```bash
curl -X POST http://127.0.0.1:8000/threat-model-projects/{id}/import/php \
  -H "Authorization: Bearer $TOKEN" \
  --data-binary @threat-model.php
```

`PhpDslReader` разбирает файл через AST (никогда не делает `require`
для загруженного файла — см. ADR-08) и выводит всё, что выходит за
рамки распознаваемого подмножества, как предупреждение, а не ошибку:
вы получаете частичную модель, а не отказ.

## Ваша KB продолжает работать

Укажите загрузчику KB в Studio на существующую директорию KB вместо
встроенной — параметр `kb_paths` в
`apps/api/config/services.yaml` — список, где более поздние пути
переопределяют более ранние (то же наслоение, которое уже делает сам
`YamlKbLoader`). Формат YAML для KB не менялся.

## Что вы получаете, и что остаётся только для CLI

| Возможность | Чистый `hybridtm` | Studio |
|---|---|---|
| Запуск анализа | `hybridtm analyze` | Тот же Rule Engine, через API или холст |
| Компиляция в Threagile | `hybridtm compile` | Тот же кодек, через `export/threagile` |
| Персистентность | Управляете файлом сами | История `ModelVersion`, оптимистичная блокировка |
| Многопользовательский режим | — | Мультитенантность, RBAC на уровне проекта (5 ролей) |
| Управление (governance) | — | Workflow Draft→Approved, policy-as-code |
| Журнал изменений | История вашего VCS | Неизменяемый `AuditLogEntry` на каждое изменение |
| Визуальное редактирование | — | Холст Studio |

Полный переход не обязателен: `hybridtm analyze`/`compile` остаются
полностью рабочими автономными командами, и CI-пайплайны, построенные
вокруг них (см. [GitHub Action
hybridtm-analyze](https://github.com/hybridtm/hybridtm/tree/main/.github/actions/hybridtm-analyze)),
не требуют запущенной Studio вообще.
